# Lessons

* [Capability artifact paths must stay inside the integrity boundary](capability-artifact-paths-must-be-integrity-bounded.md) - Locked capability manifests must not resolve executable or instruction paths outside the artifact whose bytes were hashed.
* [Script-free npm materialization still installs peer dependencies](npm-ci-materializes-peer-dependency-closure.md) - A checked runtime dependency can cause npm ci to auto-install a much larger peer closure whose advisories must be reviewed separately.
* [Cross-resource validators must enforce cardinality before invariants](manifest-validator-cardinality-must-fail-closed.md) - Validation that compares package and capability metadata must reject missing or extra resources before running one-item invariants.
* [Crossed coordination messages require state-anchor reconciliation](crossed-messages-require-state-anchor-reconciliation.md) - Before repeating destructive branch instructions from delayed asynchronous messages, compare their stated head and open action with the current remote and latest coordinator ruling.
* [Peer omission must align materialization, audit, and runtime proofs](peer-omission-must-align-materialization-audit-and-tests.md) - Omitting an unused npm host peer is safe only when install and audit scopes match and tests prove required resources remain while the peer and its imports are absent.
* [setup-node npm caching needs an explicit nested lock path](setup-node-cache-needs-nested-lock-path.md) - GitHub Actions setup-node fails before installation when npm caching is enabled but the repository's only lockfile is nested and cache-dependency-path is absent.
* [Tracker integration docs need an explicit support matrix](tracker-integration-docs-support-matrix.md) - Task integrations that mention projects or documents must distinguish supported commands, UI-only operations, ownership boundaries, and relationships between project context and executable issues.
